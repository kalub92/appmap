# app-instrument — instrument an iOS app for the map, 01 R1–R8

Runs on the main agent. Only this skill edits `app-map/ids.yaml` and the one `deep_link_scheme` key of `app-map/ios/manifest.yaml`, and only it runs `gen-ids`, `migrate-id` and `xcodebuild`; the subagents never touch `app-map/`. Working files: `app-map/.local/instrument/plan.json` and `report.md` (git-ignored). Contracts: `reference/survey-plan.md` (plan schema), `reference/id-rules.md` (ids, kinds, flags, reuse), `reference/swiftui-patterns.md` and `reference/uikit-patterns.md` (code shapes), `reference/debug-wiring.md` (deep links, fixtures, export, probe, scheme, flags), `reference/verify-and-report.md` (checks, routing, report).

## Steps
0. **Preflight.** Record `app.src_roots`, `app.layout` (`repo_root`, `app_src_dirs`, `generated_swift`, `kotlin_present`, `default_scan_dirs`), `project_style`, `wiring_placement`, `flags`, `scheme` and `xcode` per the preflight table in `reference/debug-wiring.md`. A missing `-D APP_MAP_DEBUG` is decision D0, never edited; a second `appmap` scheme in the workspace is the only reason to ask the human for a suffix now (issue #25). Pilot entries a real app lacks become `retire` decisions: never deleted here, and their `marker_unreferenced` is expected until answered.
1. **Survey.** Dispatch `app-instrument-surveyor` once per top-level source dir (≤ 40 files / ≤ 6k LOC per call; split larger dirs) with the file list, the registry ids + kinds, the generated constant names and the `app` facts. Merge the slices into `plan.json`; validate with the Ajv command in `reference/survey-plan.md`.
2. **Registry.** `reference/id-rules.md` §F (reuse), then §A–§E (propose), then §G (conflicts and renames). Edit `ids.yaml` only — screens (`title` only when static; `deep_link: appmap://<id>` or `none`), gates (`dismiss`; `controls[]` each with explicit `intent_critical`, issue #24), elements — never an existing entry's `title`, `kind` or flags (validate rule 2). Write canonical, then `tools/app-map-mcp/bin/app-map validate` and `export --check`. Run `scripts/app-map/gen-ids` for both platforms (`--platforms ios` only when `kotlin_present` is false: `lint-ids` runs `gen-ids --check` over both outputs when both exist). Re-read `AppMapID.swift` and fill `constant` on every item (`AppMapID.Screen.<x>`, `.Element.<x>`, `.Gate.<x>`, `.Gate.Dismiss.<x>`, `.Gate.Control.<x>`); one not found stays `null` and becomes a naming decision. A chosen suffix: set `deep_link_scheme` in `manifest.yaml` (that key only; `build` fields stay quoted strings, issue #20; the validate warning is expected), add the `scheme` wiring item and the `CFBundleURLTypes` human step.
3. **Dispatch.** Group items by file and files by `owner`; batches ≤ 8 files / ≤ 1,500 LOC; **serial** — parallel specialists would lint the same `--src` root mid-edit. `app-instrument-swiftui` takes `swiftui` files, `app-instrument-uikit` takes `uikit`; the batch holding `app.entry_point.file` also carries the `wiring` items. Each call gets its slice, `app` and its reference path. Collect `unplanned[]`: add to `ids.yaml`, regenerate, fill constants, re-dispatch only those files — two rounds max.
4. **Verify.** `reference/verify-and-report.md`: `gen-ids --check`, `lint-ids --platform ios --src … --instrumented ios --json`, `validate`, `export --check`, the three compiler-substitute checks, `xcodebuild` when `xcode` is true; route each failure by its table, within its bounds.
5. **Report.** Fill the D0–D10 template; print it in chat and copy it to `app-map/.local/instrument/report.md`.

## Rules
A rename is `migrate-id OLD NEW --dry-run` shown, the human's yes, the real run, then re-dispatch of the affected files — never a casual edit (01 R2). Never edit `project.pbxproj`, `Info.plist`, `.xcconfig`, `.mcp.json`, `app-map/policy/**`, `AppMapID.swift`, `.storyboard` or `.xib`; never commit. `appMapScreen` stays a container plus its 1 pt marker (issue #15); no id ever lands on a SwiftUI `List`, `Section` or `ForEach` (issue #19). The agents' grants and safety rules: 05 §5.1.
